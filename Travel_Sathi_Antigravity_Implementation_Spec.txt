  working logic.

  TypeScript + Tailwind + Supabase application.

B. SOS
-------
This is the most important workflow.

Flow:
1. Tourist opens /tourist/sos
2. Show large SOS control.
3. Explain what happens before activation.
4. On activation show confirmation dialog.
5. Request browser geolocation.
6. Call the existing Supabase RPC:
       trigger_sos(_lat, _lng, _accuracy, _location_text, _description)
7. RPC already prevents duplicate active SOS incidents.
8. After success redirect to /tourist/emergency or incident detail.
9. Show:
   - incident reference
   - current status
   - location sharing state
   - emergency contacts
   - call emergency service actions
   - live timeline
10. Realtime updates should change the UI when responder actions happen.
11. Tourist must be able to cancel only when database rules permit it.

IMPORTANT:
- Do not fake SOS success.
- Do not create a local-only SOS.
- Handle denied location permission gracefully.
- SOS must still be creatable without coordinates if necessary.
- Clearly explain that location sharing improves response.
